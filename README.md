## ページは3つ

| ファイル | 画面 | 使う人 |
|---|---|---|
| `order.html` | お供えを贈る（商品 → 名札 → 確認） | お客様 |
| `orders.html` | 注文管理（70件の一覧・PDF出力） | 葬儀社様 |
| `name-tag.html` | 名札作成（一覧から選ぶと右に立ち上がる・微調整・PDF出力） | 葬儀社様 |

### 名札作成の画面

**1画面です。左の一覧で名札を選ぶと、右にその名札が立ち上がります。**
左右はそれぞれ別にスクロールするので、一覧を送りながら右で直せます。

左は絞り込み（葬家・札種・状態・名義）と一覧。チェックしたものをPDFで出力します。
「個別に作成」で葬家に紐づかない名札を足せます。

右は上から3つです。

1. **刷り上がり**　プレビューと数値（文字サイズ・字送り・列数／段数・縦の占有・効いた制約）
2. **名札の内容**　宛先（葬家・商品・枚数）、札の種類、個人／法人、頭に大きく置く語、続柄の有無、
   よく使う名義・肩書のワンタップ候補、夫婦（名だけ入力）、「字が出ない」からの旧字・異体字選択、
   備考・メモ、外字の自動検出、複製／下書き保存／確定する
3. **この1枚の微調整**　フィールドごとに ±5 段階（相対比率方式）。mm表示が同時に動きます。

入力すると、右のプレビューと左の一覧が同時に変わります。

「一括取り込み」だけは手順が5段階あるため、別画面に切り替わります。

`index.html` は3つへの入口です。

## GitHub Pages への置き方

1. リポジトリを作り、このフォルダの中身を**そのまま**ルートに置く
2. Settings → Pages → Source を `Deploy from a branch`、ブランチを `main` / `(root)` に
3. `https://<ユーザー名>.github.io/<リポジトリ名>/` で開きます

パスはすべて相対です。サブディレクトリに置いても動きます。
`.nojekyll` を同梱しているので、Jekyll の処理は走りません。

## 微調整したものを差し替える

### 組み方の値を変える

`assets/fuda.js` の `MEAS` だけを書き換えてください。**3画面すべてに同時に反映されます。**
HTML は触りません。

```js
const MEAS={
  mTop   :0.048,  // 上余白 ÷ 札の高さ
  mBottom:0.094,  // 下余白 ÷ 札の高さ
  mSide  :0.045,  // 左右余白 ÷ 札の幅
  colp   :1.08,   // 列ピッチ ÷ 文字サイズ
  lhMax  :2.30,   // 均等割りで字間を伸ばす上限
  sx     :1.00,   // 字幅
  vf     :0.34,   // 縦位置（余白のうち上に置く割合）
  perRow :4,      // 1段あたりの人数
  mode   :'justify',
  capNa  :0.90,   // 個人名の上限 ÷ 札の幅
  capCn  :0.55,   // 名前（法人）
  capCo  :0.22,   // 会社・団体名
  capTi  :0.22,   // 肩書
  capRel :0.14,   // 続柄（小）
  capLead:0.55,   // 続柄（大）
};
```

値はすべて**札の寸法に対する比率**です。mm ではなく比率で持っているので、
同じ縦横比のサイズ違いを足しても、そのまま使えます。

ファイル冒頭の「版数」を更新しておくと、どの版が載っているか画面左下に出ます。

### 札の種類を増やす・寸法を変える

同じく `assets/fuda.js` の `FORMATS` です。

```js
const FORMATS={
  seika :{key:'seika' ,name:'生花札'        ,call:'450×150',W:150,H:450,…},
  houmei:{key:'houmei',name:'芳名札'        ,call:'340×100',W:100,H:340,…},
  slope :{key:'slope' ,name:'スロープ・枕札' ,call:'240×90' ,W:90 ,H:240,…},
};
```

`W` が よこ、`H` が たて（mm）。キーを足せば、3画面の選択肢・PDFの分割先が自動で増えます。

### 書体を差し替える（★順番が大事です）

名札の書体は `assets/font.css` の1枚で決まります。3画面とPDFがすべてここを見ています。

いま入っているのは**代用の書体**（Google Fonts の Yuji Syuku）で、モリサワ書体ではありません。

**替える手順**

| 順 | すること | さわるファイル |
|---|---|---|
| 1 | **替える前に** `font-check.html` を開き、「いまの書体を基準として記録する」を押す | — |
| 2 | 書体を差し替える | `assets/font.css` |
| 3 | もう一度 `font-check.html` を開いてはかる。出た2行を貼る | `assets/fuda.js` の `MEAS` |
| 4 | `name-tag.html` の一覧で70パターンの「収まり」を見る | — |
| 5 | **ここから**1枚ずつの微調整に入る | `name-tag.html` |

**なぜ順番が大事か**　余白・列ピッチ・文字サイズは、パターン表70種を
**「紙の上で墨が乗っている大きさ」**で実測した値です。書体を替えると、
同じ文字サイズを指定しても墨の乗る大きさが変わるため、実測値がそのままではずれます。
`MEAS.face`（字面率）でその差を吸収すると、他の値をすべて作り直さずに済みます。

先に微調整をしてから書体を替えると、調整した ±5 の値がすべて別の意味になり、やり直しになります。

**ライセンスについて**　フォントファイルは、ご契約をお持ちの側からご提供ください。
公開リポジトリ（GitHub Pages）にフォントファイルを置くのは配布にあたる可能性があります。
置き方は `assets/font.css` の【A】【B】をご覧ください。

### CSVで一括取り込みする

名札作成 → 「一括取り込み」です。5段階に分かれています。

1. **テンプレート**　札種ごとにCSVを配ります。Excelでそのまま開けるよう BOM付きUTF-8 です。
2. **読み込み**　UTF-8 / Shift_JIS を自動で見分けます。
3. **自動で割り当て**　1つのセルに社名・肩書・氏名が混ざっていても分解し、個人か法人かも見分けます。
4. **1件ずつ確認**　プレビューを見ながら確認します。確度の低いものを先頭に並べます。
5. **名札リストへ追加**　下書きとして入ります。開いて確定すると出力の対象になります。

**列は1行＝1名義**です。同じ「注文番号」の行をまとめて1枚の名札にします。
連名12名なら12行。横に広がらないのでExcelで扱いやすくなります。

```
注文番号, 葬家, 商品, 枚数, 区分, 頭に置く語, 1段の人数,
会社種別, 会社・団体名, 肩書, 氏名, 続柄, 名義（自由入力）, 備考
```

構造化した列を埋められない場合は、**「名義（自由入力）」の1列だけ**でも構いません。

**分け方の規則は、お預かりしたパターン表70種から起こしています。**
70種をいちど「自由入力1列だけ」の最も雑なCSVに落としてから読み直す試験で、
70枚すべて元どおりに復元できました。確度が下がるのは「㈱／相模生花」のように
**会社種別と屋号を別の列に組む**6パターンだけで、これらは「要確認」として先頭に出ます。
これは読み取りの誤りではなく、**組み方の指定**なので、人が見て決める場所です。

規則を直すときは `assets/csv.js` の `TYPES`（会社種別）・`TITLES`（肩書）・
`ORG_TAIL`（組織の語尾）です。

### 名義や葬家・商品を変える

`assets/data.js` です。

- `_SEED` … 名札パターン70種の名義。番号はお預かりしたパターン表の枠番号
- `FUNERALS` … 葬家
- `ITEMS` … 商品（`fmt` でどの札を使うかを決めています）
- `ORDERS` … 上の3つから自動で組み立てた注文70件

### メニュー・配色

`assets/nav.js`（サイドバー）、`assets/biz.css`（管理画面）、`assets/app.css`（お客様フォーム）。

## PDFについて

- **札の種類ごとに分かれて**出ます。生花札・芳名札・スロープ／枕札の3ファイルです。
- ページの大きさは**札の実寸**です（生花札なら 450×150mm）。
- 注文管理からは選択した注文をまとめて、名札作成からは選択した名札をまとめて出せます。
- 1枚だけの確認出力もできます（注文管理の右側）。
- **背景は塗っていません。** 名札用紙そのものに色や木目が入っているため、PDF には
  黒のインクだけを載せています（透過PNG）。画面では紙の色を付けて見せていますが、
  書き出すときは `.fuda.print` が効いて、背景・枠・影がすべて外れます。

動作確認済みの出力例：

```
名札_生花札_20261009.pdf          150.0 × 450.0 mm   3ページ
名札_芳名札_20261009.pdf          100.0 × 340.0 mm   2ページ
名札_スロープ・枕札_20261009.pdf    90.0 × 240.0 mm   2ページ
```

ブラウザによっては、複数ファイルの連続ダウンロードに確認が出ます。
その場合は「許可」を選んでください。

## 値の出どころ

| 項目 | 出どころ |
|---|---|
| 札の寸法・上下の余白 | ヒアリングシート「名札の種類」のご回答 |
| 左右の余白・列ピッチ・字幅・縦位置 | 名札パターン表70種の見本を実測 |
| 連名の上限（個人12名・法人2件） | ヒアリングシート「組み方」のご回答 |
| 名義のダミー70種 | 名札パターン表の見本を読み取ったもの |

実測の要点：縦の印字領域は札の高さの **86%**、上余白は余白全体の **34%**、
横の占有 **0.91**、列ピッチは文字サイズの **1.08倍**、文字の幅/高 **0.97**（ほぼ正体）。
どの見本も縦の占有が 0.84〜0.87 に揃っていたため、文字を先に決めて字間を伸縮させる
「均等割り」で組んでいます。

## 承知しておいていただきたいこと

- **保存はされません。** 画面を閉じると入力は消えます。営業・確認用のモックです。
- **名義の読み取りに誤りが残っている可能性があります。** 見本の解像度が低く、
  特に 037・054・046、049の12名、029・036の肩書が2つ並ぶものは確証がありません。
- **姓と名のあいだの空き**は、現状つねに半コマ空けています。見本では詰まった札で
  空きを取っていないため、込み入った札では文字が1割ほど小さく出ます。ここは仕様の論点です。
- 名札の書体は Google Fonts の Yuji Syuku を使っています。モリサワ楷書体ではありません。
- PDF の解像度は 12px/mm（約305dpi）です。変えるときは `assets/pdf.js` の
  `PX_PER_MM` と `SCALE` を調整してください。
